API Reference

Public facade

RepoWhisper

The main Facade for the Excode library. This class orchestrates the entire process from fetching the repository to answering complex questions using AI agents.

It follows the Dependency Inversion Principle by accepting any language model that adheres to the BaseChatModel interface.

__init__(source_target, llm, user_level=UserLevel.JUNIOR, context_budget=TokenUtilities.DEFAULT_CONTEXT_BUDGET)

Initializes the Excode engine.

Parameters:
  • source_target (str) –

    A public GitHub HTTP(S) repository URL.

  • llm (BaseChatModel) –

    The initialized LangChain chat model.

  • user_level (UserLevel, default: JUNIOR ) –

    Default JUNIOR. The user level used to tell the llm how the explanation should be

    JUNIOR: large explanation MID: mid level explanation SENIOR: very short explanation

  • context_budget (int, default: DEFAULT_CONTEXT_BUDGET ) –

    Maximum estimated tokens of evidence (static facts, module notes, directory tree) handed to the Architect and the Storyteller. Lower it for small context windows or strict rate limits; the pipeline compresses the notes to fit.

generate_documentation()

The main public method. Orchestrates source retrieval and automated LangGraph analysis.

Returns:
  • str | None –

    A formatted JSON string ready for a frontend UI if there is no error, else it returns None

analyze(json_path=None, port=8543)

Execute full analysis if json_path is None, save data and launch react interface locally. If json_path is passed the analysis is not executed and the interface starts immediately

Parameters:
  • json_path (str | Path | None, default: None ) –

    JSON file path of a previous analysis.

  • port (int, default: 8543 ) –

    port value for the web interface.

  • UserLevel.MID: medium-depth explanations.
  • UserLevel.SENIOR: concise explanations.

Orchestration

ProjectState

Bases: TypedDict

The global shared state for the RepoWhisper LangGraph orchestration. Acts as the central communication blackboard for all agents, ensuring type safety and predictable data flow.

AgentsWorkflow

Constructs and executes the LangGraph state machine for analyzing repositories.

Pipeline: Tracer -> (Navigator <-> local Laya/Vega Reviewer) per file -> static Facts and budgeted evidence -> Architect -> Storyteller. The Architect and the Storyteller run AFTER the per-file analysis so they work on grounded evidence instead of on the bare directory tree.

pagerank(graph, damping=0.85, iterations=50, tolerance=1e-09)

Plain power-iteration PageRank (no external dependency).

An edge A -> B means "A imports B", so rank flows towards the modules that many other modules depend on: the structural core of the project.

Parameters:
  • graph (dict[str, list[str]]) –

    adjacency list (file -> files it imports).

  • damping (float, default: 0.85 ) –

    classic PageRank damping factor.

  • iterations (int, default: 50 ) –

    maximum number of iterations.

  • tolerance (float, default: 1e-09 ) –

    early-stop threshold on the L1 change between iterations.
Returns:
  • dict[str, float] –

    dict[str, float]: rank per node, summing to ~1.0.

Grounding

FileCard dataclass

A compact, one-line description of a file used as prompt evidence.

EvidencePacker

Packs per-file cards into a text that is guaranteed to fit a token budget.

Strategy (a budget-aware, bottom-up "collapse", like a map-reduce summarization that follows the directory structure instead of arbitrary chunks):

  1. Group cards by directory. If everything fits the budget, nothing else happens and zero LLM calls are made.
  2. Otherwise collapse directories into short summaries, LEAST important first (importance = PageRank of the files they contain), and stop as soon as the text fits. The most central modules therefore keep their full detail.
  3. If every directory is already collapsed and it is still too big, lift the blocks one directory level up and repeat (recursive collapse).
  4. A final deterministic trim guarantees the budget is respected.

The collapse is done with the injected summarizer (an LLM call per block, each call bounded by chunk_budget). Without a summarizer, or if it fails, a deterministic summary (key files + file names) is used, so packing never crashes the pipeline.

pack(cards, budget)

Parameters:
  • cards (list[FileCard]) –

    one card per analysed file.

  • budget (int) –

    maximum estimated tokens of the returned text.
Returns:
  • str( str ) –

    grouped module notes, important areas placed at the start and at the end.

GroundingVerifier

Checks that every code reference (text in backticks) in a generated document really exists in the repository.

It is a pure-Python existence check, like the "existence ratio" used to evaluate documentation generators: it catches invented file names, classes, functions, libraries, flags and environment variables. It does NOT judge whether a description of behaviour is correct.

Complexity: O(L) in the length of the text, each lookup is O(1) on hash sets.
